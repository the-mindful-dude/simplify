## Reproduction

- Baseline (before any change): `pnpm --filter @simplify-dev/cli test` — `Test Files 14 passed (14)`, `Tests 200 passed (200)`.
- Before fix: `pnpm --filter @simplify-dev/cli exec vitest run --config ../../vitest.shared.ts test/init.test.ts` — `Test Files 1 failed (1)`, `Tests 5 failed (5)`.
  - First failure, `test/init.test.ts:69`: `AssertionError: expected false to be true // Object.is equality` on `expect(existsSync(configPath())).toBe(true)` — no `simplify.config.json` was created.
  - Dry-run failure: the only log call was `"ℹ [dry-run] Would initialize simplify configuration."`; no intended filenames were printed.
  - All five failures were reproduced with a fresh temp project root (`vi.spyOn(process, 'cwd')`) before touching production code.

## Root cause

- `packages/cli/src/commands/init.ts:22-24` (original) — the real-run branch only printed `"Configuration initialization is delegated to the installation subsystem."` and never called `saveConfig` or `writeLockFile`, so `doctor`'s `Run simplify init` remediation (`doctor.ts:50` and `doctor.ts:170`) could never create the files it checks.

## Fix

- `packages/cli/src/commands/init.ts:13-17` — resolve the target root from an optional `context.cwd` (defensive; the actual `CommandContext` in `cli.ts:5-13` has no `cwd`) and otherwise `process.cwd()`, which is the same root `doctor.ts:264` checks. No public interface changed.
- `packages/cli/src/commands/init.ts:19-33` — build a schema-valid config with `ProjectDetector` + `initConfig` (`config.ts:119`), falling back to defaults when no project markers exist.
- `packages/cli/src/commands/init.ts:47-48` — check `existsSync(join(cwd, CONFIG_FILE_NAME))` and `lockFileExists(cwd)` before any write.
- `packages/cli/src/commands/init.ts:56-63` — dry-run prints the intended action per file and returns before writing.
- `packages/cli/src/commands/init.ts:65-86` — real run writes missing files with `saveConfig(config, cwd)` (`config.ts:113`) and `writeLockFile(createEmptyLockFile(), cwd)` (`lockfile.ts:338`, `lockfile.ts:90`), preserving existing files; write failures are wrapped with `toCliError` (`project-context.ts:74`) into structured `CliError`. No new dependencies; no writes outside the target root.

Policy decision: existing config/lockfiles are preserved (not overwritten), following the no-overwrite rule in `library-init.ts:351-368` and AGENTS.md §4.5. Unlike `library-init`'s hard `FILE_EXISTS` rejection, `init` reports "already exists; leaving it unchanged" and still creates the other missing file — this is required so `doctor`'s lock-file remediation works when a config already exists.

## Regression test
